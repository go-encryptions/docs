# serpent — Serpent block cipher

`github.com/go-encryptions/serpent`

```go
import "github.com/go-encryptions/serpent"
```

Package `serpent` implements the **Serpent** block cipher (Anderson, Biham and
Knudsen, AES finalist) as a standard
[`cipher.Block`](https://pkg.go.dev/crypto/cipher#Block): 16-byte blocks and
16-, 24- or 32-byte keys. It is bitsliced Go with AVX2 assembly kernels on
amd64, with no cgo and no dependency beyond the standard library.

Its first consumer is VeraCrypt-volume support in `go-fde/veracrypt`, which
needs Serpent under [`go-encryptions/xts`](https://github.com/go-encryptions/xts) with 256-bit keys.

## Byte order

There are two conventions for the byte order of Serpent's key, plaintext and
ciphertext. This package uses the **standard** one, the same as Botan,
VeraCrypt and the Linux `serpent` algorithm: block and key are read as
little-endian 32-bit words. It does not use the reversed order of Linux's
`tnepres` nor of the original submission's test files.

## API

```go
func NewCipher(key []byte) (cipher.Block, error)

type KeySizeError int // returned for any key length other than 16, 24, 32
```

`Encrypt` and `Decrypt` follow the `cipher.Block` contract: `dst` and `src` may
be the same slice (in-place), and a buffer shorter than 16 bytes panics.

```go
block, err := serpent.NewCipher(key) // serpent.KeySizeError if len(key) is not 16, 24 or 32
if err != nil {
    return err
}
block.Encrypt(ct[:16], pt[:16])
```

## Batch API and AVX2

The returned cipher also has `EncryptBlocks(dst, src []byte)` and
`DecryptBlocks(dst, src []byte)`, which process every 16-byte block of `src`
independently (ECB mode): `len(src)` must be a multiple of 16, `dst` at least as
long, and the two must overlap entirely or not at all. `go-encryptions/xts` uses
them automatically.

On amd64 with AVX2 they run generated assembly kernels: Botan's 8x32 layout
(four vectors, a 4x4 transpose of 32-bit words, 32 rounds, transpose back), with
two independent groups interleaved for a 16-block kernel. The kernels are
generated by [go-asmgen](https://github.com/go-asmgen/asmgen) from the S-box
expressions of `sbox.go` themselves, so the pure-Go code stays the oracle. The
CPU and OS are probed at start-up; without AVX2, under the `purego` build tag,
and on every other architecture the portable four-block Go loops run, with the
same output.

Measured on an AMD Ryzen 9 7950X, one core, 4 KiB per call: 1312 MiB/s encrypting
and 1329 MiB/s decrypting, against 934 and 1078 MiB/s for Botan 3.14.1's AVX2
build (1.40x and 1.23x), and 1691 and 2021 MiB/s for its AVX-512 build, which
this package does not yet have. See the
[README](https://github.com/go-encryptions/serpent#readme) for the table.

## Verification

- All 1047 vectors of Botan's `src/tests/data/block/serpent.vec` (all three key
  sizes), which fixes the byte order above.
- A differential corpus of 750 random vectors generated from the Botan command
  line by `internal/genbotan`.
- A fuzz test cross-checking `Encrypt`/`Decrypt` round trips and the batch path
  on up to 40 blocks.
- The AVX2 kernels against the one-block path for every length from 0 to 70
  blocks, at several source and destination alignments, in place and out of
  place (assembly is invisible to `go cover`, so this test holds it).
- 100 % statement coverage, with the race detector, on amd64 and arm64, and
  under QEMU on big-endian s390x.

See the [README](https://github.com/go-encryptions/serpent#readme) for the
benchmark against Botan on arm64 and amd64.
